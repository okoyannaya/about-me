# AGENTS.md — about-me

## 1. Обзор проекта

`about-me` — персональный сайт-резюме. Проект развивается постепенно: описание разделов, возможностей и архитектуры дополняем по мере их появления.

Сейчас реализована базовая оболочка Angular-приложения, серверный рендеринг, гидратация и переключение светлой, тёмной и системной темы. Выбор темы хранится в cookie; начальное значение передаётся с сервера через `TransferState`. Маршруты для отдельных разделов резюме пока не добавлены.

## 2. Технологический стек

- **Фреймворк:** Angular 21, standalone-компоненты, Angular Router, signals, Angular CLI и `@angular/build`.
- **Библиотека UI:** внешняя библиотека не подключена; используются собственные компоненты в `src/app/shared/components/`.
- **Язык:** TypeScript 5.9 со строгой типизацией и строгой проверкой Angular-шаблонов.
- **Стилизация:** SCSS, локальные стили компонентов и общие CSS-переменные в `src/styles.scss`; темы используют `color-scheme` и `light-dark()`.
- **Серверный рендеринг:** `@angular/ssr`, Express 5, клиентская гидратация с повторным воспроизведением событий.
- **Дополнительные библиотеки:** RxJS 7.8 и `tslib`.
- **Тесты:** Vitest 4 и jsdom через Angular CLI.
- **Качество кода:** ESLint, Angular ESLint, typescript-eslint, `eslint-plugin-import`, `eslint-import-resolver-typescript`, `eslint-config-prettier` и Prettier.
- **Пакетный менеджер:** npm; используем `package-lock.json`. Точные версии зависимостей проверяем в `package.json` и lock-файле перед изменением конфигурации.

## 3. Основные команды

Все команды выполняются из корня проекта.

| Команда                                                             | Назначение                                                                                                           |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `npm ci`                                                            | Установить зависимости по `package-lock.json`.                                                                       |
| `npm start`                                                         | Запустить сервер разработки; стандартный адрес — `http://localhost:4200`.                                            |
| `npm run build`                                                     | Собрать production-версию приложения и SSR-сервер в `dist/about-me/`.                                                |
| `npm run watch`                                                     | Пересобирать приложение в режиме development при изменении файлов.                                                   |
| `npm run serve:ssr:about-me`                                        | Запустить собранный SSR-сервер; сначала выполнить сборку. Порт по умолчанию — `4000`, переопределяется через `PORT`. |
| `npm test`                                                          | Запустить тесты через Angular CLI.                                                                                   |
| `npm test -- --watch=false`                                         | Выполнить тесты однократно.                                                                                          |
| `npm run typecheck`                                                 | Проверить TypeScript приложения и тестов без генерации файлов.                                                       |
| `npm run lint`                                                      | Проверить TypeScript и Angular-шаблоны с помощью ESLint.                                                             |
| `npm run lint:fix`                                                  | Применить безопасные автоматические исправления ESLint.                                                              |
| `npm run format:check`                                              | Проверить форматирование Prettier.                                                                                   |
| `npm run format`                                                    | Отформатировать файлы Prettier.                                                                                      |
| `npm run ng -- generate component shared/components/component-name` | Создать компонент средствами Angular CLI.                                                                            |

Проверка `typecheck` не заменяет Angular-сборку: корректность шаблонов проверяется компилятором Angular при сборке. Команды форматирования и автоисправления могут менять много файлов; проверяем diff и не затрагиваем несвязанные пользовательские изменения.

## 4. Архитектура и структура папок

```text
.agents/skills/angular-coding-rules/  # Обязательный скилл с 46 правилами
.vscode/                            # Настройки редактора и рекомендуемые расширения
public/                             # Статические файлы, копируемые при сборке
src/
  app/
    core/                           # Пока пустая заготовка
    features/                       # Пока пустая заготовка для функциональных разделов
    layout/                         # Пока пустая заготовка для компоновки
    shared/
      components/
        card/                       # Общий компонент карточки
        icon/                       # Кнопка-иконка с подписью при наведении
        theme-toggle/               # Переключатель темы
      constants/
        index.ts                    # Имена доступных SVG-иконок (ICONS)
      icons/                        # Исходные SVG-иконки
      services/
        theme.service.ts            # Тема, cookie, состояние SSR/браузера
        theme.service.spec.ts
    app.ts / app.html / app.scss     # Корневая оболочка
    app.spec.ts
    app.config.ts                   # Провайдеры приложения, роутер и гидратация
    app.config.server.ts            # Серверные провайдеры
    app.routes.ts                   # Клиентские маршруты
    app.routes.server.ts            # Режим рендеринга серверных маршрутов
  main.ts                           # Запуск в браузере
  main.server.ts                     # Запуск Angular на сервере
  server.ts                         # Express и обработчик Angular SSR
  styles.scss                       # Общие стили и токены темы
  index.html
```

- Новые возможности группируем по функциональности; общие компоненты и сервисы размещаем в `shared/`. Отдельные каталоги для функциональности, типов или компоновки создаём по мере необходимости.
- Тесты храним рядом с проверяемым кодом; шаблон и SCSS — рядом с компонентом.
- При серверном рендеринге учитываем отсутствие браузерных API. Доступ к `window`, cookie браузера и другим браузерным возможностям выполняем в подходящем контексте; используем Angular DI и проверки платформы.
- Сохраняем согласованность начального состояния сервера и браузера при гидратации. Для персонализированного по cookie HTML не включаем общее публичное кеширование без пересмотра поведения темы.

### Именование файлов и папок

- Для собственных файлов и директорий используем `kebab-case`: `theme-toggle/`, `user-profile/`, `contact-links.ts`, `theme.service.ts`, `theme.service.spec.ts`. Точки в суффиксах обозначают роль файла.
- Не смешиваем `kebab-case` со `snake_case`, `camelCase` или `PascalCase` в путях.
- Имена компонентов, интерфейсов, типов и enum в коде записываем в `PascalCase`: `ThemeToggle`, `UserProfile`, `ThemeMode`.
- Для служебных и конфигурационных файлов сохраняем имена инструментов: `package.json`, `package-lock.json`, `angular.json`, `tsconfig.json`, `tsconfig.app.json`, `tsconfig.spec.json`, `eslint.config.mjs`, `.prettierrc`, `.prettierignore`, `.editorconfig`, `.gitignore`, `AGENTS.md`, `README.md`, `SKILL.md`.

### Импорты и алиасы

- Внутри одного компонента или близко связанных файлов используем относительные пути `./` и `../`.
- Если путь требует двух и более переходов к родительской папке (`../../` и глубже), используем подходящий существующий алиас или создаём предметный алиас в `compilerOptions.paths` файла `tsconfig.json`.
- Алиасы называем по назначению: `@components/*`, `@services/*`, при реальной необходимости — `@types/*`, `@features/*`, `@layout/*`. Не создаём общие алиасы `@/*` или `@shared/*` и алиасы для ещё не существующих каталогов.
- При добавлении алиаса проверяем его разрешение в сборке, тестах и ESLint и обновляем порядок групп импортов, если появляется новая группа.

В `tsconfig.json` уже настроены следующие алиасы:

| Алиас           | Каталог                       |
| --------------- | ----------------------------- |
| `@features/*`   | `src/app/features/*`          |
| `@layout/*`     | `src/app/layout/*`            |
| `@components/*` | `src/app/shared/components/*` |
| `@services/*`   | `src/app/shared/services/*`   |
| `@constants/*`  | `src/app/shared/constants/*`  |

`@features/*` и `@layout/*` относятся к существующим пустым заготовкам; новые алиасы добавляем только при необходимости для реального кода.

Компонент `app-icon` принимает обязательные `icon: ICONS` и `label: string`, необязательные `size` (число в пикселях, по умолчанию 24), `color` (CSS-цвет), `isPressed` (состояние кнопки-переключателя), `lightIcon` и `darkIcon` (варианты по системной цветовой схеме), а также выдаёт событие `(clicked)`. `label` задаёт доступное имя кнопки и нативную подсказку через `title`; время её появления определяет браузер. Для новой иконки достаточно поместить SVG в `shared/icons/` и добавить её имя в `ICONS`: `angular.json` копирует все SVG из этой папки в `/icons/`, а компонент строит путь из имени. `ThemeToggle` передаёт системному варианту `system-light.svg` и `system-dark.svg` через необязательные входы; `system.svg` служит запасным вариантом. Выбор по системной схеме делает CSS до гидратации. Выделение выбранной темы плавно перемещается между иконками; при предпочтении уменьшенного движения анимация отключается.

## 5. Правила написания кода

### Обязательный скилл проекта

- Перед любым написанием или изменением кода прочитай целиком [angular-coding-rules](.agents/skills/angular-coding-rules/SKILL.md) и применяй его без отдельного напоминания пользователя.
- Следуй всем 46 правилам скилла непосредственно во время реализации, исправления ошибок, рефакторинга и написания тестов. Это относится к TypeScript, компонентам, сервисам, шаблонам, стилям, серверному коду и конфигурации, связанной с кодом.
- Если скилл не появился в списке доступных, открой указанный `SKILL.md` напрямую. Перед завершением проверь изменения по применимым правилам и выполни соответствующие проверки проекта.

### Форматирование и импорты

- Используем настройки `.editorconfig` и `.prettierrc`: два пробела, одинарные кавычки в TypeScript, ширина строки `100`; HTML форматируется Angular-парсером Prettier.
- Группы обычных импортов располагаем в порядке: встроенные модули Node.js (`node:*`) → пакеты `@angular/*` и их подпути → `rxjs` и его подпути → остальные внешние библиотеки → внутренние алиасы → относительные импорты → стили и ассеты.
- Между группами оставляем пустую строку. Внутри групп сортируем пути и именованные импорты по алфавиту; сортировку задаём в `eslint.config.mjs`.
- Внутренние алиасы группируем в порядке `@features/*` → `@layout/*` → `@components/*` → `@services/*` → остальные предметные алиасы. Новую группу добавляем при появлении соответствующего алиаса; не создаём папки ради этой схемы.
- Типы импортируем через отдельный `import type`. Типовые импорты остаются в группе своего источника. `import * as` используем только при необходимости; предпочитаем именованные импорты, когда они подходят.
- Импорты с побочными эффектами — полифилы, регистрация модулей, глобальные стили — не переставляем автоматически. Полифилы и необходимую раннюю регистрацию размещаем отдельной группой перед обычными импортами; стили — после них. Сохраняем порядок выполнения и CSS-каскад внутри таких групп.
- Порядок импортов проверяет `import/order` из `eslint-plugin-import`; явные импорты типов — `@typescript-eslint/consistent-type-imports`. Prettier отвечает за форматирование, ESLint — за правила кода и импортов.
- В VS Code используем рекомендуемые расширения из `.vscode/extensions.json`: Angular Language Service, ESLint и Prettier. Настройки сохранения находятся в `.vscode/settings.json`: форматирование Prettier и автоисправления ESLint; отдельную автоматическую перестановку импортов редактором не включаем.

### TypeScript и Angular

- Сохраняем строгие настройки TypeScript и `strictTemplates`. Для неизвестных данных используем `unknown` и проверки, очевидные типы выводим автоматически.
- Не используем TypeScript-геттеры в шаблонах никогда. Производные реактивные значения оформляем через `computed()`, другие значения — через явно обновляемые поля; чтение signals в шаблоне разрешено.
- Применяем современные Angular API, поддерживаемые установленной версией. В проекте Angular 21: не переносим предположения о значениях по умолчанию или стабильности API из Angular 22 без проверки.
- Соблюдаем KISS, DRY и SOLID; удаляем потерявшие назначение части изменяемой логики после проверки использования в TypeScript, шаблонах, маршрутах, DI и публичном API.

### Строковые значения

- Повторяющиеся строковые значения режимов, статусов и других вариантов выносим в строковые `enum`.
- В логике, компонентах и тестах используем элементы `enum`, а не дублируем их строковые значения. Например: `ThemeMode.Dark` вместо `'dark'`.

### Стили и CSS-переменные

- Общие стили и CSS-переменные храним в `src/styles.scss`; стили конкретного компонента — в его SCSS-файле.
- Перед созданием новой CSS-переменной обязательно проверяем существующие переменные и их использование. Переиспользуем уже объявленные токены цветов, отступов и шрифтов; не создаём другое имя для того же значения и назначения.
- Сейчас объявлены шкалы `--text-*`, `--background-*`, `--primary-*`, `--secondary-*`, `--accent-*`. Общие токены отступов и шрифтов добавляем при появлении реальной потребности.
- Новым общим токенам даём смысловые имена в `kebab-case` и учитываем светлую, тёмную и системную темы.

## 6. Тесты

- Названия тест-кейсов в `it` и `test`, включая параметризованные тесты `it.each` и `test.each`, пишем на русском языке.
- Название описывает проверяемое поведение. Например: `сохраняет выбранную тему после обновления страницы`.
- Проверяем наблюдаемое поведение: отображение данных, пользовательские действия, события и состояния. Для изменений SSR и темы учитываем серверное состояние и гидратацию.
- Файлы тестов называем `*.spec.ts` и размещаем рядом с проверяемым кодом. Используем существующую конфигурацию Angular CLI и Vitest.

## 7. Обязательный чеклист перед завершением задачи

- Проверить изменения по применимым правилам скилла `angular-coding-rules` и этому файлу.

- Проверить именование, порядок импортов, `import type`, отсутствие относительных импортов с `../../` и глубже и дублирующих CSS-токенов.

- Если изменились структура папок, зависимости, алиасы, команды или существенное поведение проекта, обязательно обновить соответствующие разделы `AGENTS.md`.
- При добавлении или удалении npm-пакетов обновить `package.json` и `package-lock.json` согласованно.
- Проверить итоговый diff, сохранить несвязанные пользовательские изменения и кратко сообщить, что изменилось, какие проверки выполнены и какие ограничения остались.
