# Написание кода по правилам проекта

## Когда применять

Применяй скилл при каждом создании или изменении кода в текущем репозитории `about-me`.
Запросы «добавь компонент», «исправь ошибку», «отрефактори сервис», «измени стили»
и «напиши тест» относятся к этому скиллу. Для объяснения кода или работы только
с документацией скилл сам по себе не требует изменений приложения.

## До первой правки

- Прочитай целиком [все 46 правил](references/coding-rules.md). Это обязательная
  часть скилла для любого написания кода, включая небольшие исправления.
- Прочитай применимые `AGENTS.md`, начиная с корня репозитория, и соседний код.
  Соблюдай актуальные правила импортов, алиасов и CSS-токенов из `AGENTS.md`
  вместе с правилами скилла.
- Проверь состояние рабочего дерева, `package.json`, lock-файл и относящиеся
  к задаче настройки Angular и TypeScript. Определи версии и доступные проверки.
  Условия для Angular 22+ применяй только к соответствующей версии проекта.

## Во время написания кода

- Следуй всем применимым правилам непосредственно при реализации; итоговая
  проверка дополняет их применение, а не откладывает его до конца работы.
- Сохраняй обязательные соглашения проекта и в коде, взятом из сторонних примеров.
  Приватные поля называй с `_` перед смысловым именем; учитывай это при выборе
  имён булевых полей, зависимостей, Observable и signals по правилам 10–13, 24 и 28.
- Применяй правила к создаваемому и изменяемому коду. Удаляй потерявшие назначение
  части затронутой логики после проверки использования. Сохраняй несвязанные
  пользовательские изменения; не расширяй задачу до миграции всего проекта.
- Используй API установленной версии. При необходимости уточняй их поведение
  по источникам в конце файла правил; перечитывать все внешние источники для
  каждой правки не требуется.

## Перед завершением

- Проверь итоговый diff по всем 46 правилам в применимой к изменению части.
  Исправь нарушения, включая запрещённые обращения к геттерам из шаблонов.
- Выполни существующие проверки, соответствующие изменению, по актуальному
  `AGENTS.md` и `package.json`. Не объявляй отсутствующие или невыполненные
  проверки успешными.
- Обнови `AGENTS.md`, если изменились структура, зависимости, алиасы, команды
  или существенное поведение проекта.
- Сообщи результат: что изменилось, какие проверки выполнены и какие
  ограничения остались. Отдельный отчёт по каждому из 46 пунктов не требуется.
