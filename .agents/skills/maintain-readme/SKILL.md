# Поддержка README.md

Цель — короткая и актуальная документация проекта для разработчика.

1. Описывай только текущее состояние проекта; не включай отсутствующие, планируемые и пустые части.
2. Новую возможность добавляй в обзор одной короткой формулировкой без подробностей реализации.
3. Структуру показывай на уровне значимых каталогов и ответственности, не перечисляй каждый файл.
4. Не документируй API отдельных компонентов, сервисов и тестовых файлов.
5. Скиллы описывай только на уровне назначения; не копируй их правила в README.md.
6. Не дублируй сведения, которые надёжнее получать из конфигурации; для изменчивых данных указывай источник истины.
7. Не накапливай историю изменений: устаревшую информацию заменяй или удаляй.
8. Обновляй только раздел, затронутый изменением.
9. После редактирования проверь документ на противоречия, устаревшие утверждения и повторы.

При изменении стека, зависимостей, команд, алиасов или структуры прочитай [project-facts.md](references/project-facts.md).
