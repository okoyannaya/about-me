# Структура кода about-me

- Выбирай простую структуру под реальную задачу. Группируй код по функциональности и разделяй ответственности только при разных причинах изменения.
- Переиспользуемую логику выноси, когда у неё общий смысл; не создавай абстракции и интерфейсы без потребителя.
- Перед удалением проверяй использования в TypeScript, шаблонах, маршрутах, DI и публичном API. Удаляй заменённые и неиспользуемые части.
- Собственные пути называй в `kebab-case`; связанные `.ts`, `.html`, `.scss` и `.spec.ts` сохраняют общее базовое имя.
- Общие компоненты и сервисы размещай в `shared/`; новый каталог создавай только при фактическом содержимом.
- При создании или изменении алиаса прочитай [aliases.md](references/aliases.md).
- При добавлении или удалении пакета прочитай [dependencies.md](references/dependencies.md).
