# Поддержка AGENTS.md

Цель — короткий документ с актуальными проектными фактами, а не энциклопедия кода.

1. Описывай только текущее состояние проекта; не включай отсутствующие, планируемые и пустые части.
2. Новую возможность добавляй в обзор одной короткой формулировкой без подробностей реализации.
3. Структуру показывай на уровне значимых каталогов и ответственности, не перечисляй каждый файл.
4. Не документируй API отдельных компонентов, сервисов и тестовых файлов.
5. Не дублируй подключённые скиллы и правила, автоматически контролируемые ESLint, Prettier, TypeScript или редактором.
6. Оставляй только соглашения, которые нельзя надёжно получить из конфигурации или тематического скилла.
7. Не накапливай историю: устаревшую информацию заменяй или удаляй.
8. Не требуй полный набор проверок после каждой задачи. Тесты рекомендуй только при возможном влиянии на тестируемое поведение.
9. При изменении структуры, стека или существенной возможности обновляй только соответствующий короткий раздел.
10. После редактирования проверь документ на противоречия, устаревшие утверждения, повторы и факты, уже доступные из других источников.

При изменении стека, зависимостей, команд или алиасов прочитай [project-facts.md](references/project-facts.md).
